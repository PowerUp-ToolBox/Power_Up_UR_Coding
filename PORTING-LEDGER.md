# Porting ledger

Hidden knowledge is a non-obvious fact the code depends on that a rewrite would easily lose: verified-live wire-protocol facts, OS bugs and workarounds, ordering and race guarantees, defensive parsing, safety rules, timing constants with a reason, and state-reset rules.
Every row needs an owner (a powerup-core slice, the stage 2.1 bridge, or stays in Swift), a disposition (test, doc-comment or N/A) and a status. CI fails while any row's status is the placeholder word for unfinished work (spelled T-O-D-O, matched case-insensitively anywhere in this file), so that word must never appear here, not even in prose.
Core-owned rows say "pending slice 2.x" until their slice lands, and that slice's PR must update its rows to point at the Rust test or doc comment that now carries the rule. "covered" means the evidence already carries it; a core-owned row whose disposition is N/A is "covered" too, since no slice has anything to port for it. "gap: ..." marks an item whose code has already landed (stays in Swift, or the 2.1 bridge) with no test or comment pinning it yet.
This ledger was reconstructed on 2026-10-28 from the code, the tests and DESIGN.md, because the plan's original ~131-item list was never written down. It holds 407 rows (384 reconstructed, plus HK-385 onwards added by the slices). Line numbers refer to the tree at commit 36f7744, except in rows a slice has since updated, which cite the tree that slice left. The original plan counted about 131 items; this count is higher because each rule is its own row.
